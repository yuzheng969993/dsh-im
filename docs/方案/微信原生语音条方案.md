# 微信原生语音条方案

## 目标

让微信（iLink Bot）渠道能够发送微信原生语音条，并把这项能力接入 DSH 插件体系：

- 每个微信机器人可在「更多设置 → 语音交互」独立开启，默认关闭。
- 文字答案始终保留；语音条是额外的原生呈现，不替代文字。
- 支持两种触发方式：仅在用户发送语音消息时回复语音，或每条回复都附带语音。
- Harness 通过 `dsh_im_return_file` 返回的音频文件，在语音能力开启时优先按语音条发送，失败后回退为音频附件。

## 协议要点

iLink 的语音发送由三部分组成：

1. `ilink/bot/getuploadurl` 使用 `media_type: 4`（VOICE）申请 CDN 上传参数；
2. 音频按 AES-128-ECB + PKCS7 加密后上传 CDN，`x-encrypted-param` 作为下载参数；
3. `ilink/bot/sendmessage` 发送 `item_list: [{ type: 3, voice_item: {...} }]`：

```json
{
  "type": 3,
  "voice_item": {
    "media": { "encrypt_query_param": "...", "aes_key": "base64(hex)", "encrypt_type": 1 },
    "encode_type": 6,
    "bits_per_sample": 16,
    "sample_rate": 24000,
    "playtime": 2380
  }
}
```

`encode_type` 取值：1=pcm、2=adpcm、3=feature、4=speex、5=amr、6=silk、7=mp3、8=ogg-speex。本实现使用：

| 编码 | encode_type | 采样率 | 说明 |
| --- | --- | --- | --- |
| SILK | 6 | 24 kHz | 微信原生语音格式，优先 |
| Ogg/Opus | 8 | 48 kHz | silk-wasm 缺失时由 ffmpeg 生成 |

## 配置

```json
{
  "voice": {
    "enabled": true,
    "ttsProvider": "dashscope",
    "endpoint": null,
    "secretRef": "DASHSCOPE_API_KEY",
    "ttsModel": "qwen3-tts-flash",
    "ttsVoice": "Momo",
    "responseFormat": "wav",
    "customBody": null,
    "customResponse": "audio",
    "replyMode": "voice-input",
    "codec": "auto",
    "maxChars": 200,
    "ffmpeg": null
  }
}
```

### 合成服务

| `ttsProvider` | 请求 | 凭据 |
| --- | --- | --- |
| `dashscope` | `POST` DashScope 原生 multimodal-generation，返回 `output.audio.url` | 必填 |
| `openai` | `POST {endpoint}/audio/speech`，body 为 `{model,input,voice,response_format}`，支持直接音频或 JSON URL/Base64 | 可选 |
| `custom` | `POST {endpoint}`，body 为自定义 JSON；支持 `{{text}}`、`{{voice}}`、`{{model}}`、`{{format}}`、`{{hash}}`、`{{id}}` 占位符 | 可选 |

`{{hash}}` 对相同文本、音色、模型和返回格式稳定，适合自建服务的幂等缓存；`{{id}}` 每次请求唯一，适合必须新建文件的接口。自定义响应用 `customResponse` 指定：`audio`（直接音频字节，默认）、`url`（JSON 中的音频 URL）、`base64`（JSON 中的 Base64）。音频 URL 支持相对路径；同源下载会带上 Bearer 凭据。

- `endpoint`：OpenAI 兼容服务填到 `/v1`，自定义接口填完整 URL；支持 http/https，因此可指向内网或 VPS。
- `secretRef` 只保存凭据库中的环境变量名，密钥值不进入机器人配置；自建无鉴权服务可留空。
- `replyMode`：`voice-input` 或 `always`。
- `codec`：`auto`、`silk`、`ogg-opus`。
- `maxChars`：播报文本上限，默认 200；超出部分仍完整保留在文字回复中。
- `ffmpeg`：可选路径，默认使用 PATH 中的 `ffmpeg`。

### 自建 TTS 示例

OpenAI 兼容（例如带 OpenAI 适配层的 GPT-SoVITS / CosyVoice / XTTS）：

```
ttsProvider: openai
endpoint: http://127.0.0.1:9880/v1
ttsModel: tts-1
ttsVoice: alloy
```

自定义 JSON（例如 GPT-SoVITS api_v2）：

```json
{
  "ttsProvider": "custom",
  "endpoint": "http://127.0.0.1:9880/tts",
  "customBody": "{\"text\":\"{{text}}\",\"text_lang\":\"zh\",\"ref_audio_path\":\"/path/ref.wav\",\"prompt_text\":\"...\"}",
  "customResponse": "audio"
}
```

自定义接口的响应必须是音频字节、JSON 中的音频 URL，或 JSON 中的 Base64 音频；其他结构会被明确报错并按语音失败处理。

不要把密钥写进 `customBody`；需要鉴权时把密钥放进插件凭据库，把变量名填到 `secretRef`，运行时会以 `Authorization: Bearer …` 发送。若你的 VPS 服务只接受表单、GET 查询参数或非 Bearer 的鉴权头，需要在服务前加一层 JSON/OpenAI 兼容适配。

### 已接入验证：香港 VPS 的 ttsd

`ucloud-hk` 上运行 `ttsd.service`（`/srv/services/ttsd/ttsd_server.py`，edge-tts，监听 `127.0.0.1:8781`）：

- `GET /health`、`GET /voices`
- `POST /tts`：`{"text":"...","voice":"zh-CN-XiaoxiaoNeural","id":"...","rate":"+0%"}`，返回 `audio/mpeg`
- `id` 相同且文件已存在时复用，因此必须让 `id` 随文本变化

Windows 侧已有 `D:\tools\ucloud-ports-tunnel.ps1`（计划任务 `ucloud-ports-tunnel`）把 VPS 的 `8781` 转发到本机 `127.0.0.1:8781`，DSH 可直接使用：

```json
{
  "enabled": true,
  "ttsProvider": "custom",
  "endpoint": "http://127.0.0.1:8781/tts",
  "secretRef": null,
  "ttsVoice": "zh-CN-XiaoxiaoNeural",
  "responseFormat": "mp3",
  "customBody": "{\"text\":\"{{text}}\",\"voice\":\"{{voice}}\",\"id\":\"dsh-{{hash}}\",\"rate\":\"+0%\"}",
  "customResponse": "audio",
  "replyMode": "voice-input",
  "codec": "auto",
  "maxChars": 200
}
```

已实测：通过该隧道合成中文 MP3，再经 ffmpeg + silk-wasm 转为 24 kHz SILK，语音条数据生成成功。ttsd 的 `out/` 目录没有自动清理，长期使用建议在 VPS 增加按时间清理的 timer。`/voices` 返回的音色是裸名（如 `XiaoxiaoNeural`），请求时要使用完整名（如 `zh-CN-XiaoxiaoNeural`）。

## 降级与已知限制

- 缺少 DashScope 密钥：DashScope 合成禁用；自建 OpenAI 兼容/自定义接口不受影响，文字与文件能力也不受影响。
- 缺少 `silk-wasm`：`auto` 自动改用 Ogg/Opus；显式选择 `silk` 时明确失败。
- ffmpeg 不可用或转码失败：语音条发送失败，自动回退为音频文件附件。
- 语音合成或发送失败：文字答案已经送达，回合不因语音失败而失败；状态中记录 `voiceSendErrors` 与 `lastVoiceError`。
- 微信语音条约 60 秒上限；超过时记录警告，不阻断发送。
- iLink 出站 `VOICE` 在部分账号/客户端版本上会被服务端接受但客户端静默丢弃。这不是本地编码错误；可切换 `codec` 试探，或依赖始终保留的文字回复。README 已明确说明这一上游不确定性。
